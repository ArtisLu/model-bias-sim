How it fits together

There is one entry point, _targets.R. It reads config/config.yml, loads every function in R/, and declares the targets (the cached steps). targets::tar_make() runs whatever is out of date and stores each result in _targets/. Nothing in R/ runs on its own: each file only defines functions, and each function takes data in and returns a result, without reading files or global settings.

The scripts follow the paper's steps. The colour of a stage is the same in every diagram and table on this page.

Inputs and seeds Data (Step 1) CCW analysis under test (Steps 1, 5) Reference DGM (Steps 2–3) Truth and calibration (Step 3) Replicates (Steps 3–5) Performance and adjustment (Steps 6–7) Outputs

Folders and scripts

Files you edit are in R/, config/ and tests/. Files the pipeline writes are in _targets/ and reports/. Raw data are never modified.

Target dependencies

Each box is a target; its second line names the script whose function computes it. An arrow means the target on the right uses the result on the left, so changing a box reruns everything downstream of it and nothing upstream. Every box in the four middle columns and the outputs column (except fig_estimates and the Word draft) exists once per active dataset, with the suffix _maringe in the store; the suffix is left out here.

Left out to keep the picture readable: every simulated-world target also reads base_data, and truth also reads dgm; correction also reads obs_result and the null-scenario replicates; the *_all targets only stack the per-dataset results. For the live, complete graph run targets::tar_visnetwork().

Inside one replicate

The two heaviest targets, as chains of function calls. Both reuse the same simulation and analysis functions, so the truth and the replicates cannot drift apart.

sim_results: one replicate b

  1. run_batch() simulate.R picks replicates of this batch
  2. draw_replicate_rng(seed_b) utils.R: u_event, seed_aux, u_cens
  3. simulate_outcomes() dgm.R
    • invert_weibull_tv() event time, θ switches on at the treatment date
    • censoring: administrative at day 365.24 for Maringe; where a censoring model is fitted (SynPUF), a second invert_weibull_tv() draws the loss-to-follow-up time
  4. safely_run(run_pipeline) utils.R, pipeline.R
    • ccw_grace_vs_none() → build_clones(), weight_control() (Cox model for time to surgery), weight_surgery() (logistic model at 6 months) → split_clones()
    • fit_outcome() weighted Cox, robust SE
  5. One row: estimate, SE, CI, p, status, message, θ, rep, seed, counts

truth and calibration

  1. calibrate_theta() truth.R secant search, starts at θ̂
  2. compute_truth(θ) truth.R
    • stack_copies() 250 copies of the 200 patients (50,000)
    • for each of 24 truth seeds: draw_replicate_rng() → simulate_outcomes() → run_pipeline(robust = FALSE)
    • mean of the 24 estimates and its MCSE
  3. Same truth seeds at every θ, so ψ(θ) is smooth and the search converges in a few steps
  4. make_truth_table() performance.R sets the null truth to exactly 0 and keeps ψ(0) as a diagnostic

Random numbers and reproducibility

  • make_crn_seeds(seed_master, B) draws one seed per replicate index b, once. Replicate b gets the same seed in both scenarios (common random numbers), so the θ* and null scenarios differ only in θ.
  • draw_replicate_rng(seed) makes all draws for one replicate in a fixed order: event uniforms, an auxiliary seed, then censoring uniforms. New components are appended at the end, so adding the censoring model left the event-time draws of v0.2 unchanged.
  • The truth uses its own seed (seed_truth) with the same 24 seeds at every θ.
  • Results are identical whatever the batch size or number of workers (tested in test-pipeline.R).
  • Each replicate's estimate, SE, status and error or warning message is stored in sim_results; failed fits are counted and excluded from the measures.

Running and reading results

testthat::test_dir("tests/testthat")                         # unit tests
Sys.setenv(R_CONFIG_ACTIVE = "smoke"); targets::tar_make()   # quick end-to-end check
Sys.unsetenv("R_CONFIG_ACTIVE"); targets::tar_make()         # full run
source("reports/paper/build_section4.R")                     # Word draft for paper Section 4

targets::tar_visnetwork(targets_only = TRUE)   # interactive dependency graph
targets::tar_outdated()                        # what would rerun
targets::tar_read(performance_maringe)          # performance by scenario
targets::tar_read(sim_results_maringe)          # one row per replicate
targets::tar_read(table_results_maringe)$performance   # Table 5 as a data.table
targets::tar_meta(fields = c(name, seconds))   # run time per target

To change something, edit the function or the config value and run tar_make() again; only affected targets rerun. For example, changing the DGM covariates reruns dgm and everything after it, but not obs_result.

  • archive/two-datasets: the pipeline exactly as run on 5 Oct 2026 (Maringe and SynPUF). Kept unchanged.

Open points for the next iteration

  • Add renv.lock from your machine; this run used R 4.3.3, targets 1.4.1 and tarchetypes 0.7.12 without crew (sequential, about 32 minutes).
  • Run R in a UTF-8 locale (the default on Windows with R 4.2 or later, and on macOS). Switching the locale of an existing _targets/ store marks every target as outdated and triggers a full rerun.
  • Move build_section4.R into the pipeline once the text is stable.
  • Rewrite qba_report.qmd for one dataset, or retire it in favour of the paper outputs.
